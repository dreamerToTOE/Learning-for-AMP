# R1 AMP 并行环境容量与小样本机制审计

日期：2026-11-24

本报告对应提交前的容量测试。测试使用独立 Isaac Lab v2.1.1 环境、Isaac Sim 4.5.0 Kit Python、skrl 1.4.3、RTX 3070 8 GiB、CUDA 设备 `cuda:0`，固定 seed 42。每组均使用官方 `Isaac-Humanoid-AMP-Walk-Direct-v0` 与 `skrl_walk_amp_cfg.yaml`，只覆盖并行环境数，其他任务、网络、奖励和训练参数保持一致。

## 2. 2 环境小样本机制

官方配置的关键值如下。

- rollout 长度为 16，`memory_size=-1` 会把 rollout memory 设为 16。
- `mini_batches=2`，因此每次更新的 PPO 总样本数是 `16 × N`，每个 PPO mini-batch 是 `8 × N`。N=2 时分别是 32 和 16。
- GAE 使用 `gamma=0.99`、`lambda=0.95`，沿每个环境自己的 16 步 rollout 维度反向计算。优势值随后在这 32 个样本上统一做均值和标准差归一化。它不是按 episode 或按 mini-batch 单独归一化。`terminated | truncated` 都会截断 GAE，`time_limit_bootstrap=False`。
- AMP 在每次更新先向 motion dataset 追加 512 个参考状态，但判别器本次真正抽取的 batch 大小仍由 `memory_size × num_envs` 决定。N=2 时从 motion dataset 抽取 32 个状态，再分成两个 16 的 mini-batch。
- reply buffer 非空后使用同样的 32 个状态抽样，再分成两个 16 的 mini-batch。首次更新在 reply buffer 为空时，代码回退使用当前 rollout 的 AMP 状态作为 replay 输入。之后每次更新向 reply buffer 追加 `16 × N` 个当前策略状态，N=2 时为 32 个。
- `discriminator_batch_size=4096` 在本轮 N≤256 的测试中只是上限，并没有把小 batch 补到 4096。N=2 时判别器每个 mini-batch 实际使用 16 个策略状态、16 个 replay 状态和 16 个专家状态，共 48 个输入状态。每次外层更新有 6 个 learning epochs 和 2 个 mini-batches，因此按三类输入合计处理 `6 × 2 × 48 = 576` 个状态，其中每一类各 192 个。每一类每次更新的唯一抽样数仍是 32，两个 mini-batch 在 6 个 epoch 中重复使用同一批张量。
- Actor、Critic 和 Discriminator 共用同一次 AMP 更新的两个 PPO mini-batch，外层每次更新执行 12 次优化器步骤。小 batch 下每个优化器步骤只看 16 个 rollout 样本，GAE 和优势归一化的统计量也只来自 32 个样本。RandomMemory 以 replacement 方式抽样，因此会补足固定的 16 个位置，但不会增加独立样本量。

这个机制解释了此前 2 环境训练的局限。它确实能完成正常的前向、反向和 checkpoint 写入，但每次更新的 PPO 统计量很小，判别器也没有使用配置中的 4096 样本上限。2 环境结果可用于验证训练链路和数值稳定性，不能单独作为 AMP 学习能力或失败的证据。

## 3. 本轮选择与后续门槛

本机已验证的候选配置选择 256 环境。它在 50 更新测试中达到 6606.45 环境步/s，峰值显存 4859 MiB，最低空闲 2974 MiB，且没有 OOM、NaN 或 Inf。它仍远低于官方 4096 环境，因此正式长训必须保留显存监控，并先用更长的短跑确认不会随 replay buffer、日志和 episode 统计增长。

下一步先用 256 环境做单种子长跑的分阶段验证，再决定是否推进约 1M 环境交互步。训练报告应同时保留实际风格奖励、专家/策略判别器评分、每次更新样本数、动作幅度、关节目标超限比例、跟踪误差和中间 checkpoint 独立评估。当前报告不把 50 更新的 reward 或 loss 变化解释为已经学会行走。
