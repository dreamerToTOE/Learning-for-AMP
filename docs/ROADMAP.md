# 实施路线图：AMP → Motion Tracking → 鲁棒运控与部署

v0.4 · 2026-11-25。R1/R2 保持归档，R3 限时收尾；R4 保留 AMP 归档，新增 R5 Motion Tracking 与 R6 鲁棒运控/部署。后续均为规划，不代表已授权长训或已实现。

## 核心研究问题

- Q1：相比纯任务奖励 PPO，AMP 是否提高运动风格相似性？是否引入任务跟踪性能代价？
- Q2：混合行走/跑步/转向（必要时侧移）专家数据时，各技能覆盖率如何？是否存在模式坍塌？
- Q3：若技能缺失，主要是样本覆盖、指令与奖励、判别器混合分布、优化过程，还是接触动力学限制？
- Q4：条件 Actor / 条件判别器 / 均衡或自适应采样，各自贡献多大？
- Q5：训练时可使用特权 Critic，但 Actor 部署输入必须来自可获得的观测和外部指令。

## R0 — 仓库接管、环境审计、上游选择（必须首先完成）

**前置：无；不允许启动长训。**

步骤：
1. Clone 本仓库，检查当前 Git 状态；保存 `git rev-parse HEAD`、系统、驱动、CUDA、Python、GPU 显存及可用空间。
2. 只读调查本机 Isaac Sim/Isaac Lab 现存环境，确认 2.1.1 是否真实可用、版本组合是否支持 AMP 示例。
3. 核对官方 Isaac Lab 的 `Isaac-Humanoid-AMP-*-Direct-v0` 示例、使用的 `skrl` 版本、动作数据格式和训练入口。**必须以当前 checkout 的真实代码为准，不假设文档版本可直接运行。**
4. 调查 G1 备选上游 `legged_lab`、`AMP_Running_baseline`（具体许可证、版本、模型资产、数据权利、可用任务、维护状况）；择一或先保留候选。
5. 明确两条环境方案：A 在现有 2.1.1 跑官方示例；B 独立环境跑 G1 适配。禁止直接修改现有工作环境。
6. 提交 `reports/R0_environment_audit.md`：版本矩阵、依赖/风险、可运行命令、最小 smoke 计划、推荐路线和阻塞项。

验收（R0 PASS）：仓库与上游来源、环境实测、任务入口和配置、磁盘/显存预算均留痕；选定下一步路线。缺任一关键项记 PARTIAL/BLOCKED。

## R1 — 官方 Humanoid AMP 单技能基线（已归档）

R1 的目标是学习 AMP 的训练和推理流程、复现官方单技能行走，并通过同预算 PPO 对照理解专家运动先验与奖励设计的作用。

- **COMPLETE_WITH_LIMITATIONS。** 官方纯风格 AMP 的 40.96M checkpoint 在 100 个独立初态中有 97 个跑满约 10 秒。RTX 3070 实测完成 2048 环境的训练。 [冻结评估](../reports/R1_eval_freeze_40m.md)
- 速度任务完成 seed42 同预算 PPO/AMP 对照。实景和接触测量确认 PPO 利用低姿爬行取得速度奖励，速度任务 AMP 也未复现原有步态。 [同预算对照](../reports/R1_speed_tracking_seed42.md) · [奖励漏洞诊断](../reports/R1_reward_hacking_audit.md)
- 两组在原速度任务上均未形成直立行走，缺少跨训练 seed 的重复证据，无法据此判定公平直立行走任务中 AMP 全面优于 PPO。R1 的算法学习与基础复现已达到阶段目标，可以进入 R2。
- R1 的奖励迭代、对照训练和 seed43、44 复验已取消。成功与失败的 checkpoint、数据、视频及报告随实验记录冻结。

## R2 — 宇树 G1 单技能 AMP 复现

R1 的 `COMPLETE_WITH_LIMITATIONS` 满足阶段衔接。先核实 G1 的模型、许可和动作数据，再复用成熟工程里的机器人与控制框架。

第一条实验路线固定为 MimicKit 的 29 DoF G1、Newton 后端和单步行动作。基线为纯风格 AMP，评估采用固定参考相位初态及确定性 Actor。按向前位移、直立姿态和足端交替支撑验收。 [R2 上游与资产审计](../reports/R2_g1_single_skill.md)

已冻结 seed42 的 4,194,304 步 checkpoint。两个阶段的同初态评估从约 2M 时的 0/5 提升到末档 5/5。末档在新增 100 个参考相位初态上均完成 10 秒行走。R2 单技能仿真验收通过，原始动作来源与许可待核验。 [独立评估](../reports/r2_g1_single_skill/amp_4m_heldout_100.json)

1. 审计成熟的 G1 AMP 上游，核验机器人资产、专家动作、预训练权重、各自许可、软件版本及可运行证据。优先选择有单技能步态或可从混合工程筛出行走数据的实现。
2. 固定上游提交和依赖，在独立环境中先验证资产与专家轨迹。记录 G1 自由度、控制频率、动作映射、关节顺序、执行器及专家数据坐标约定。
3. 有兼容的 checkpoint 时先做仿真推理和短回放。小规模训练以行走 AMP 为主，检查姿态、前进速度、跌倒、足端接触和动作范围。其他技能留给后续数据评估。
4. 按固定初态做独立评价。有速度指令的任务同时固定指令。保存原始数据、成功和失败视频、模型校验值及最小复现步骤。报告写入 `reports/R2_g1_single_skill.md`。

R2 以 `COMPLETE_WITH_LIMITATIONS` 归档。仿真基础验收通过，冻结模型作为后续单技能基线。原始步行动作的来源和许可继续核验。R3 可以使用许可独立核实的替代数据推进。

## R3 — 多技能 AMP（限时收尾，核心必做与可选分开）

目标：掌握多技能运动先验、指令控制及独立行为评价；不是穷尽 AMP 改进。沿用已跑通的 MimicKit / Newton / G1 29DoF。R1、R2 冻结，不重新训练 PPO、不追求消除全部漂移。

| 阶段 | 优先级 | 工作与退出条件 |
| --- | --- | --- |
| R3-0 数据与轻量诊断 | 必做 | 优先许可明确的 G1 走/跑两类片段（不可用时用其他合法、可区分技能）。核对来源、许可、映射、单位、频率、循环、速度分布与预览。R2 yaw/局部横向速度/左右步态仅做评估，不重训。原始数据许可未闭合不得擅自复用或再分发。 |
| R3-1 原始多技能 AMP | 必做 | 单 Actor、单 D、纯风格，至少两类专家；评估自发模式覆盖、跌倒和实际行为。没有模式坍塌也如实归档，不制造问题。 |
| R3-2 条件 Actor | 必做 | 加入离散技能或连续速度指令，部署时条件可获取；先用普通 D。共享必要的任务、姿态/接触定义，避免 R1 奖励漏洞；评价指令响应及走跑切换。 |
| R3-3 条件判别器 | 一次对照 | 仅改变 D 是否接收条件；专家、当前策略、replay 的标签必须正确配对，数据/任务/预算一致。负结果也可结束。 |
| R3-4 对称性 | 轻量尝试 | 优先合法数据镜像（关节轴、旋转、速度和指令标签一致）；有余力才试 Actor 镜像损失。漂移若是航向无约束，不强行用镜像修复。 |
| R3-5 均衡/自适应采样 | 按需 | 只有覆盖或难度差异的证据时才做一项对照，区分专家、指令、初态采样；设置概率下限。无明显问题则跳过。 |
| R3-6 多判别器与状态门控 | 可选 | 参考 State-Dependent AMP，最小共享 Actor + 条件运动 D/门控实现；起身仅在合法数据及明确恢复终止条件就绪时尝试，不强制完成。 |
| R3-7 鲁棒性 | 移至 R6 | 不在 AMP 收尾重复做完整 DR、扰动或部署工程。 |

主要实验先用 seed42，smoke 后保存约 1M/2M/4M checkpoint；只有清晰改善且预算允许才到约 8M。单项最多一轮针对性诊断、一轮合理修正，随后归档为 PASS、PARTIAL、NEGATIVE_RESULT、BLOCKED 或 SKIPPED，说明证据与限制。初始建议 R3 新增正式训练约 2–3 小时，累计预计超出此前 4–5 小时预算或需换框架/租卡须先汇报，不自动追加。

先小规模固定初态评价，值得保留的最终模型每技能至少 30 个独立初态，最佳模型可扩至 100。记录指令成功率、真实姿态/接触、技能覆盖、切换、速度方向误差、显存/耗时与视频。单 seed 属探索性结果，不能声称跨 seed 稳健或论文级显著性。

**R3 退出门：** R3-0/1/2 已完成有证据的实现与有限预算验证，条件判别器完成一次可解释对照或记录具体阻塞；优先获得可控制的两技能策略，但失败亦可按 COMPLETE_WITH_LIMITATIONS 收尾。R3-4–6 不作为进入 R4/R5 的门槛。不要等待所有技能 100% 或所有改进获胜。

## R5 — G1 Motion Tracking / BeyondMimic（下一条主线，NOT_STARTED）

R4 AMP 归档后优先推进。优先复用公开成熟实现，先核实上游 commit、许可证、数据、checkpoint、版本和本机资源；参考 BeyondMimic（https://beyondmimic.github.io/）、MimicKit DeepMimic（已验证推理）和 Unitree RL Lab（https://github.com/unitreerobotics/unitree_rl_lab）。不要默认完整复现扩散生成或真机复杂技能。

| 阶段 | 最小交付 |
| --- | --- |
| R5-0 上游审计 | 选择一个可跑的 G1 跟踪环境；先检查预训练权重和参考数据许可，独立环境。 |
| R5-1 Motion Retargeting | 一条来源明确的人体动作到 G1 的映射、坐标/旋转/单位检查和可视化；优先复用工具。 |
| R5-2 DeepMimic / 全身跟踪 | 先理解并训练或复现一个参考动作跟踪策略，记录参考状态初始化、跟踪奖励、关节/连杆误差、跌倒及视频。 |
| R5-3 多动作跟踪 | 至少两条合法运动；按实际需要理解非对称 Actor-Critic、自适应运动采样，分别评估动作跟踪与未见初态。 |
| R5-4 BeyondMimic 进阶（可选） | 根据资源优先复现其 RL tracking 部分；潜空间、扩散蒸馏、导航/避障只做原理与现有权重验证或另立任务，不阻塞 R6。 |

区分 AMP 风格生成与显式参考跟踪；不得将 DeepMimic 简化实现称为完整 BeyondMimic。一次主线训练先按实际吞吐设置有限预算；遇阻先复用权重或缩小范围，不反复调参。结论限定在实际测试的运动与环境。

## R6 — 鲁棒运控与部署（NOT_STARTED）

目标是把策略训练、接口验证和部署串起来，兼顾求职中的 Sim2Real 核心能力。优先沿用 R3 或 R5 的可用 G1 策略，并在需要时复用成熟速度指令 PPO 控制器作参考，不重启 R1 对照。

- R6-0：明确观测/动作顺序、归一化、坐标系、控制周期、PD/力矩限幅及指令来源，导出独立推理（Torch/ONNX 任选可用方式），离线一致性及闭环时序验证。
- R6-1：Sim2Sim（优先 Newton → 独立 MuJoCo 或已可用的另一后端），验证接口、执行器、接触与轨迹偏差；不要求不同引擎逐帧一致。
- R6-2：有界 DR/扰动对照，优先摩擦、质量、PD、观测噪声及延迟；先测名义模型和扰动基线，再按证据选少量随机化。评估未见扰动，不以每项提高为门槛。
- R6-3：学习 RMA/HIM 的历史编码与适应原理；只在明确存在需要适应的动态差异且资源足够时尝试最小实验，不强制另训大型模型。
- R6-4：真机 Sim2Real 为独立授权任务。没有 G1 硬件及现场授权时保持 BLOCKED/NOT_STARTED，Sim2Sim 不冒充真机。现有机械臂 Sim2Real 仓库继续独立，不自动修改。

## 并行学习与范围

建议个人学习时间：RL 基础/诊断 20%，AMP 多技能 15%，Motion Tracking/重定向 20%，部署与适应 25%，人形动力学/WBC/MPC 15%，世界模型等前沿 5%。这是学习优先级建议，不是 GPU 预算或完成率。浮动基座、接触动力学、质心、WBC、MPC 与步态基础可与实践并行学习，不必全部写进本仓库。SuperMimic、ADP、复杂执行器辨识等暂列未来选题。R4 保留为 AMP 项目结项与简历材料，R5/R6 为后续学习与实践计划，可独立建仓（新仓库需用户另行确定），不要求所有内容都在 Learning-for-AMP 实现。

## 工作纪律与停止条件

- 每个阶段结束更新 `PROJECT_STATUS.md`，记录状态、提交、环境、证据与后继任务。
- 一阶段一个主要目标；训练前确认 GPU/显存、磁盘空间和保存频率；优先 smoke test。
- 遇到 OOM、训练 NaN、姿态发散/接触异常：立即停止并记录，不无限重试；先做最小诊断。
- 不为了制造亮点伪造模式坍塌、提升百分比或真机结果；方法基于已有文献，创新点侧重问题定位与工程实验。
