## R0

### R0.1 已有 Isaac 环境无法直接运行官方 AMP

- **背景** 需要先在现成官方 Humanoid 上验证 AMP，建立迁移 G1 前的参照。
- **问题** 已有 Isaac Lab v1.2.0 工作树包含其它项目改动、没有官方 Humanoid AMP，最小场景导入失败。有的 Conda 环境只有 Isaac Sim，有的只有 Isaac Lab 或 skrl 2.x。
- **分析** 证据支持源码、Kit 扩展、Python 和 skrl 版本组合不完整。官方训练入口的最低版本检查不能证明全部配置字段兼容。具体缺包与运行问题见两次 smoke。
- **方法** 固定 Isaac Sim 4.5.0、Isaac Lab v2.1.1、Kit Python 3.10.15、skrl 1.4.3。先用 4 环境、16 个控制步做 headless 验证，后续换为带 Git metadata 的独立 checkout，补上 sparse checkout 缺失的 `isaaclab_mimic`。
- **效果（完全解决入口启动）** 官方 Walk 完成 16/16 rollout，Actor、Critic、Discriminator 初始化，退出 0。程序启动和一次更新的证据范围到此。
- **新问题** 初次运行借用了 Conda site-packages，迁移和复跑仍可能依赖隐式包。
- **面试复习** 说明为什么同时核查任务注册、原生扩展、动作文件和 Python 导入路径。一条 `import torch` 不能替代最小训练。
- **证据** [R0 提交 `5d22605`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/5d22605) · [环境审计与原始命令](../reports/R0_environment_audit.md) · [本机 stdout 与 checkpoint](AMP_G1_ARTIFACT_INDEX.md#r0)

### R0.2 隔离 Python 后暴露隐式依赖

- **背景** 官方入口已跑通，需要可重复安装，也要能比较 AMP 和 PPO。
- **问题** 第一次真正隔离启动找不到 `flatdict`，补齐后又缺 `h5py`。
- **分析** 两个包来自先前的 ambient site-packages。Kit Python 提供 PyTorch 和仿真扩展，项目 venv 提供锁定的用户态依赖，职责要分开。
- **方法** 建独立 venv 并锁包，入口清掉继承的 `PYTHONPATH`，禁用 user site-packages。补 `flatdict==4.0.1`、`h5py==3.13.0`，核查 `sys.path` 无旧 Conda、用户目录和 ROS 路径。
- **效果（完全解决该组复跑依赖）** AMP、PPO 各完成 4 环境、16 步，退出 0。末档 SHA-256 与之前对应 smoke 一致。
- **新问题** 两个 smoke 峰值整卡显存为 7,132 / 6,360 MiB。后续首先在 2 环境测训练链路，再单独审计并行容量。
- **面试复习** 解释版本锁为什么要含传递依赖，为什么还要记录 Git SHA、模型、运行命令和可执行解释器。
- **证据** [隔离提交 `9f38f20`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/9f38f20) · [失败目录及重跑结果](../reports/R1_amp_baseline.md#4-真正独立-venv-重跑) · [依赖锁](../configs/r1/requirements-venv.lock) · [运行入口](../scripts/r1_python.sh)

### R0.3 资源预算需要在真实硬件上实测

- **背景** 初始计划用 4070 的显存预算推演官方并行训练。
- **问题** 本机实际可见 RTX 3070 8,192 MiB。其它 Isaac Sim 进程和图形桌面会占整卡显存。
- **分析** `nvidia-smi` 显示的驱动 CUDA 13.0 与 Kit PyTorch 编译的 cu118 是不同层。启动和短测峰值也会混入其它进程。
- **方法** 记录设备、驱动、Torch CUDA、进程和运行前后显存，训练中固定间隔采样。保留 OOM 失败和原参数成功重跑的记录。
- **效果（部分解决）** 得到可用的 8 GiB 基线。后来的 R1 高并行恢复和速度 AMP 长跑都曾采到 0 MiB 空闲，说明资源上限随运行路径和共用进程而变。
- **新问题** 需要将环境数、实际交互步数、mini-batch、显存余量和墙钟时间一同纳入容量选择。
- **面试复习** 区分进程峰值与整卡采样峰值。报告启动基线、余量和采样频率才能解释 OOM。
- **证据** [R0 资源与环境](../reports/R0_environment_audit.md) · [R1 容量实测](../reports/R1_formal_seed42_env2048.md) · [锁定环境与原始日志](AMP_G1_ARTIFACT_INDEX.md#r0)

## R1

### R1.1 训练能更新，但最初的策略大多很快跌倒

- **背景** 先验证同环境 PPO / AMP 的训练和独立评估，再做奖励消融。
- **问题** 2 环境、5 更新末档在配对初态上 AMP 9/10 跌倒，唯一超时仅净前进 0.456 m，PPO 10/10 跌倒。随后任务权重 1、风格权重 0 / 1 的六组每组 16,000 交互步，600 回合全跌倒。
- **分析** 配对初始观测哈希一致，动作和损失有限，结果支持稳定复现失败。每步任务奖励恒为 1，既没有方向也没有速度目标。六组用同一 AMP 训练入口，考察风格项权重。
- **方法** 以 Actor 均值动作独立评估，固定 100 个初态，区分跌倒与超时并保留逐步速度和失败骨架。记录 seed44 首次 OOM，外部进程退出后同配置重跑。
- **效果（无明显改善）** 六组存活均值仅约 0.48–0.68 s。风格开关对跌倒率差值为 0 个百分点，短预算下无法分离算法效果。
- **新问题** 首步动作随训练放大，需要排查关节目标和训练信号。
- **面试复习** 用“程序正常、策略失败、比较任务定义不完整”三层描述。解释为何停止把一次超时或带有前倾的位移当作走路。
- **证据** [训练和独立评估](../reports/R1_amp_baseline.md) · [六组提交 `5500405`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/5500405) · [600 回合与配对差值](../reports/r1_formal_eval/summary.json) · [本机短训、视频及模型](AMP_G1_ARTIFACT_INDEX.md#r1)

### R1.2 动作到关节目标映射超限

- **背景** 六组全跌倒后复核同一状态下的首步动作。
- **问题** 上游用软关节上下限完整宽度作为 scale，`clip_actions=false`。任务组晚期首步目标为 −5.49 至 7.96 rad，最大目标偏差 7.83 rad，CPU PhysX 报 spherical joint 角超界。
- **分析** CPU 探针和动作映射直接支持超限存在。超限对跌倒的因果贡献无法由单步日志确定。
- **方法** 做固定权重原始、仅裁剪、裁剪加半宽度三项探针，再用项目侧可选 patch 做相同 50 更新短训。保持官方 checkout 干净。
- **效果（部分解决）** 临时裁剪与半宽度把最大偏差降到 4.97 / 3.01 rad，探针仍跌倒。短训修正组无 PhysX 目标角错误，平均存活从 0.563 到 0.747 s，两组仍 10/10 跌倒。
- **新问题** 目标合法之后仍失稳。后续官方学习基线沿用原始动作映射，额外测超限率，修正版保留为诊断。
- **面试复习** 从 Actor 输出追到反归一化、offset/scale、限位、PD 和实际关节。关节物理可执行和目标角合规分别验证。
- **证据** [诊断 `51319a3`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/51319a3) · [修正 `675193b`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/675193b) · [动作 patch](../scripts/r1_action_range_patch.py) · [同初态结果](../reports/R1_amp_baseline.md#11-动作范围修正短对照2026-11-23) · [原始探针](AMP_G1_ARTIFACT_INDEX.md#r1)

### R1.3 检查重置和风格奖励量级

- **背景** 动作合法性修复后策略仍不稳定。
- **问题** 参考重置的躯干高度比原动作高约 0.15 m。某同初态 probe 的风格奖励为 4.43，原任务奖励为 1。
- **分析** 高度偏移是上游代码明确设计，不支持坐标意外错位。高风格/任务比值可能影响优势估计，无法由一次 logit 证明是主因。
- **方法** 核对相同初态、x/z 分布和上游 reset。动作修正后将 `discriminator_reward_scale` 改为 0.5，做同样 50 更新的 task+style 短对照。
- **效果（无明显改善）** 初始风格奖励约 0.80，平均存活 0.753 s，修正 task-only 为 0.747 s，均 10/10 跌倒。量级变化没消除失败。
- **新问题** 要分开看策略学习尚早、重力承载与执行器控制。风格奖励和环境记账指标后续分开记录。
- **面试复习** 奖励要看权重、原始量级、采样分布和闭环动作，单个 probe 只支持当下量级。
- **证据** [初态与风格诊断](../reports/R1_amp_baseline.md#10-六组全跌倒诊断2026-11-23) · [缩放短对照](../reports/R1_amp_baseline.md#12-修正接口下的风格尺度短对照2026-11-23) · [诊断记录索引](AMP_G1_ARTIFACT_INDEX.md#r1)

### R1.4 合法参考目标的开环回放也失稳

- **背景** 想隔离 learned action 与资产是否能承载。
- **问题** 30 Hz 控制直接跟踪 60 Hz 参考的隔一帧位置目标，去掉 reset 抬升及保持初始姿态的原设置回放均约在第 17 步跌倒。关重力可计满 77 步，根部却漂到 z≈4.35 m。
- **分析** 回放不依赖 PPO 输出，支持首步越界无法独自解释所有失稳。指出重力和接触承载是敏感条件。无重力结果只用于隔离变量。
- **方法** 在有重力下固定模型和起始条件扫 solver iterations。默认 4/0 到 16/4，完成步数 18→49，32/4 又降到 17。位置迭代在 12、14、16、18、20、24 的窄扫中同样出现非单调变化。
- **效果（部分解决诊断）** 延长了特定开环回放，对策略学习成败的推断仍缺证据。
- **新问题** 需检查驱动解析和传感器是否扰动场景。后续纠正了把开环回放完成度当训练硬门槛的做法。
- **面试复习** 给关节 PD 喂参考目标与 Actor 根据实时状态反馈是两层控制。开环诊断可暴露接口问题，与闭环通过条件分开。
- **证据** [回放诊断 `d196dd0`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/d196dd0) · [solver sweep `183f0ab`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/183f0ab) · [回放代码](../scripts/r1_reference_replay.py) · [原始探针与命令](AMP_G1_ARTIFACT_INDEX.md#r1)

### R1.5 USD drive 与接口张量不一致

- **背景** 原始参考回放的膝关节明显没有跟上目标。
- **问题** 运行时左右肘、膝的 stiffness/damping/effort limit 为 0，USD prim 仍有 elbow 150/15、knee 300/30。显式全局增益后膝误差仍约 2.76 / 2.22 rad。
- **分析** 初期以为填上 actuator tensor 就能修好实际驱动。源码和重复 probe 显示 implicit actuator 的计算 torque 主要用于记录，位置目标仍交给 PhysX USD drives。
- **方法** 做单位换算、drive override、直接改本地 USD 四个关节和 IdealPD effort 对照。比较逐步根部、足和目标差值。
- **效果（无明显改善，部分负面）** 假设的四个 torque 由 0 变成大数，但固定相位下三组轨迹逐步一致，63 步。真实 USD 高增益也是 63 步。IdealPD 高增益出现 NaN，低增益有效试例只到 13 / 21 步。
- **新问题** 需要区分日志诊断值与引擎施力。没有理由以更大增益替代闭环训练验证。
- **面试复习** 先追执行器是谁施力，再谈 set target 与 torque。遍历 USD 和 runtime 张量是两个证据面。
- **证据** [驱动解析 `6abc5e2`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/6abc5e2) · [高增益 USD `a63db00`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/a63db00) · [执行器探针](../scripts/r1_probe_actuator_mapping.py) · [重力诊断](../reports/R1_humanoid28_gravity_diagnosis.md)

### R1.6 接触观测、摩擦和起始相位敏感

- **背景** 需要定位首次承载时的异常并分辨接触参数影响。
- **问题** `RigidPrim(track_contact_forces=True)` 能读力，但相同 phase 30 的回放从 63 降到 26 步。底层 view 也未匹配到预期 link。
- **分析** 观察器会改变该探针的结果。接触求解、摩擦和相位会改变失稳时间，无法据一个对照断定驱动或地面为唯一根因。
- **方法** 改用基于躯干速度差分的载荷 proxy，同时保留无观察器对照。扫摩擦 0.1/0.5/1/2/5 和起始帧，检查 restitution、接触偏移与首个目标帧以及速度前馈。
- **效果（部分解决观测）** proxy 与无观测基线同为 63 步。frame 0 且 μ=0.5 达 58 步，frame 30 为 63。restitution 0.12/average 在历史计数口径下达到 68，邻近 28/32 帧仅 26/27。后续按真实参考区间重解读，见 R1.9。
- **新问题** proxy 只近似整机载荷，无法当左右脚法向力。回放结束条件还需要核对。
- **面试复习** 先验证观察器开关的 A/B，然后讨论接触力的构成、子步和归属连杆。
- **证据** [proxy `ab71e93`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/ab71e93) · [相位摩擦 `1c5ec6b`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/1c5ec6b) · [接触参数报告](../reports/R1_humanoid28_gravity_diagnosis.md) · [原始回放](AMP_G1_ARTIFACT_INDEX.md#r1)

### R1.7 参考位置与速度字段的相位不一致

- **背景** 姿态、执行器和接触检查仍无法解释起始阶段的所有差异。
- **问题** 统一高度偏移后，frame 0 reset 链路的 body position 最大误差 3.8e−7 m、关节角 0。脚部速度误差约 0.45 / 0.63 m/s。NPZ 有成对重复位姿，但对应非零速度。
- **分析** 已排除测试范围内的关节名称、轴、角度单位及位姿映射的大错位。速度与离散位姿差分不一致得到证据支持，是否主导跌倒仍不确定。
- **方法** 比较速度相位 offset、有限差分起始速度、整段 30 Hz 去重重建、速度目标及直接写回关节状态。
- **效果（产生负面效果）** 相邻速度 offset 为 27–37 步，整段重建 29 步、强制关节姿态 28 步，原始速度保留的去重版仍 63 步。改变数据一致性没有改善该闭环缺失的探针。
- **新问题** 保存原始数据和探针，不将重建速度当成最终修复。需要再核查接触几何及动力学推导。
- **面试复习** 同时验证 timestamp、插值空间、坐标约定和速度定义。参考速度和有限差分的差异要结合采样及速度定义解释。
- **证据** [结构审计 `629b171`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/629b171) · [重建试验 `dd7b987`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/dd7b987) · [重建代码](../scripts/r1_reconstruct_motion.py) · [对照记录](../reports/R1_amp_baseline.md#14-接触力摩擦和起始相位对照2026-11-23)

### R1.8 碰撞体、质量惯量和 USD 资产编辑的副作用

- **背景** 查清脚底穿透、质量来源和 composition 路径，避免按零值误读。
- **问题** 顶层 authored mass/inertia 多为占位，foot CollisionAPI 位于 instance proxy 的 payload。frame 30 几何估算左右脚底穿透分别约 6.4 / 3.0 cm。
- **分析** 15 个 PhysX body runtime 总质量约 35.73 kg。脚、手和头的示例质量与几何体积×默认密度对应。未直接枚举出碰撞 prim 不意味着没有碰撞体。
- **方法** 比较远程原资产、展平 USD、保留 payload 层的本地副本、脚盒偏移以及质量/惯量覆盖。验证状态有限并比较 COM、principal axes 写入语义。
- **效果（部分解决来源判断，修复无效）** 展平无偏移也从 63 降到 24。分层拷贝无偏移仍 63，毫米级改动反而 52–57。锁定原质量和对角惯量仍 63，缩放 0.5 / 2.0 为 41 / 32，完整属性覆盖为 38。
- **新问题** 改 USD 会耦合几何、惯性与仿真初始化。完成来源审计后，将该支线降级为历史诊断。
- **面试复习** 解释资产层级、局部和惯性坐标系、参考姿态穿透、求解器实际质量。强调保留 offset=0 的编辑路径对照。
- **证据** [几何 `3a41ee5`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/3a41ee5) · [惯量 `3419846`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/3419846) · [接触几何报告](../reports/R1_humanoid28_contact_geometry.md) · [质量与执行器报告](../reports/R1_humanoid28_gravity_diagnosis.md)

### R1.9 取消 77 步开环硬门槛

- **背景** 此前为 77 步有重力开环回放反复调资产和接触。
- **问题** 从 frame 30 按 stride 2 回放 154 帧文件，真实有效目标只有 62 步（最后一帧为末端截断）。旧 63 步已含一次额外末帧保持。早期计满但 NaN 的路径也无法判稳定。
- **分析** “未完成 77 步所以官方 AMP 资产不能学”是本轮已纠正的推断。开环有限性可以检查素材与接口，不能替代闭环独立评估。
- **方法** 默认在参考末尾截断，单独标记 raw/clamped 帧。只有显式 `--hold-final-frame` 才继续保持。暂停动力学 sweep，回到官方网络、奖励和动作映射。
- **效果（完全解决判据错误）** CUDA 实测 62 个有效控制步全部有限，`reference_end_truncated=true`，无跌倒终止。官方 Nucleus checkpoint 探针未找到可用权重，走自主训练路径。
- **新问题** 用 `trainer timesteps` 乘环境数得到交互步数，并据 rollout 长度核对 batch。
- **面试复习** 诊断要有真正的时域、有效帧及失败标志。掌握何时停止调参，回到能证伪主假设的试验。

### R1.10 两环境步数与 batch 太小

- **背景** 即使按官方纯风格配置运行，最初预算验证仍全跌倒。
- **问题** 2 环境 × 16 rollout × 2,000/5,000 updates 只有 64k/160k 实际交互。后者达到 80k trainer ticks，但仅约官方 4096 环境 × 80k 的 0.049%。
- **分析** 每更新只有 32 个 rollout 状态，PPO mini-batch 16。判别器每 mini-batch 实际看到策略、回放、专家各 16。4096 是截取上限，epoch 重复不增加采样。
- **方法** 固定官方配置做 2→256→2048 容量阶梯，并核查 GAE、归一化和 skrl D 采样。2,000/5,000 更新的 10 回合存活均值分别 0.857/0.800 s，两组均全跌倒。
- **效果（部分解决预算瓶颈）** 50 更新测试中，256 环境约 6,606 步/s、整卡 4,859 MiB。2048 环境约 34,860 步/s、5,823 MiB。选择经实测的 2048，保留长跑显存监控。
- **新问题** 需要用阶段权重的独立闭环评估判断步态是否形成，并区分速度和生存。
- **面试复习** 明确 time steps、parallel env、rollout 长度、unique samples 与 optimizer passes 的乘法关系。

### R1.11 高并行后出现稳定步态，但初始相位仍影响成功

- **背景** 容量试验允许在本机用官方网络扩大到 20.48M 交互。

- **分析** 独立倒地和视觉回放支持训练初中期尚未稳定。事件文件里 Walk 环境奖励每步 1，回合总值主要反映存活。

### R1.12 官方 40.96M 通过步行验收

- **背景** 20.48M 有真实稳定步态，但仍容易在部分初态跌倒。
- **问题** 恢复 checkpoint 没保存完整采样状态，高并行显存紧张。

### R1.13 同速度预算的 PPO / AMP 与爬行漏洞

- **背景** 公式与预算要共享，才能比较任务表现以及风格先验的加入效果。
- **问题** 官方每步奖励为 1，需加 1.5 m/s 速度目标。最初按前进和足端事件计算得分，仍会让低姿爬行计为成功。
- **分析** 终止线仅 0.5 m，躯干降低后仍能存活并赚前向速度分。配对视频和姿态复核支持 PPO 低姿前进、AMP 低姿支撑。两组都没有直立成功样本。
- **方法** 任务奖励用存活项与速度误差指数项，两组同模型、公用超参和 2048 环境，AMP 额外使用风格，原生 skrl 算法细节保留。各训 40,009,728 步，评估五档每档 100 对初态，最后评估权重为 39,976,960 步。
- **效果（产生负面效果）** PPO 82/100 持续前进，AMP 0/100，二者直立行走均 0/100。固定窗口速度 MAE 0.358 / 1.387 m/s。前者在指定奖励下更会前进，直立步态样本效率或性能优势待验证。
- **新问题** 脚或近地事件不能单独判断支撑形态。需实测非足端接触并复核公共规则。
- **面试复习** 先交代公平对照的控制项和统计分母，再解释目标错设为何允许高 reward 低任务质量。

### R1.14 验证公共直立规则，冻结 Humanoid PPO

- **背景** 需要确认爬行的真实受力，以及修复成功判据会不会误杀官方步行。
- **问题** 10 个同初态校准中，PPO 的手/小腿触地帧约 37.3% / 45.6%，速度 AMP 约 58.3% / 77.3%。官方步行均为 0。历史速度 AMP 未逐更新保存真实风格项。
- **分析** 联系视频和计量可确定低姿行为。最终 D 给官方步态 3.925、速度 PPO 0.104、速度 AMP 0.473 的回放分数，历史奖励竞争或局部最优成因仍不足以判断。
- **方法** 首先核对 ContactSensor 开关不改轨迹。原型公共规则门控躯干高度≥0.80 m、倾角≤45°、非足端法向力<10 N，连续 3 无效控制步终止。用三份冻结模型在新增 20 个初态比较原/新规则。
- **效果（部分解决）** 官方在两套规则均跑满 20/20（其中 18 符合既有直立辨识）。两种低姿策略从 19/20 与 16/20 跑满到均为 0/20。256 环境再训练试跑在共享显存最低 143 MiB、89 更新后中止。没有完成修订版学习效果对照。
- **新问题** 原任务漏洞已有充分证据，接下来的项目重点是 G1 基础复现。停止配对新训练，取消 seed43/44，冻结有效策略和反例进入 R2。
- **面试复习** 区分“门控规则能识别旧策略”和“在新规则下可训出新策略”。无历史风格日志时给出能与不能推出的结论。

### R2.3 Newton/Warp 冷编译与两类缓冲溢出

- **背景** 在独立 Python/torch/Warp 组合运行 G1 AMP smoke，再扩大至 128 环境。
- **问题** 首次 16 环境 2,048 步虽然退出 0，却出现碰撞候选溢出。128 环境 pilot 后来发生约束缓冲区溢出，在 122,880 步结束。
- **分析** 两类缓冲限制不同。首跑耗时也包含 Warp 冷编译，不能由 429 s 和重复启动 18 s 推出容量 patch 有约 24 倍提速。
- **方法** 先仅把 `nconmax` 从 200 改为 512，再将 `njmax` 从 256 改为 512。各次使用隔离 checkout、相同物理和控制设置，保留原始失败日志。
- **效果（完全解决本轮容量点的溢出）** 16 环境复测正常，128 环境复测 262,144 步且无两类溢出。底层 PD、摩擦、质量和动作接口保持相同。
- **新问题** 训练链健康后，pilot 末档 5/5 仍跌倒，需要更多交互并做阶段评估。

### R2.4 有限训练预算内形成可复测的单技能行走

### R2.5 漂移来自航向与局部横移的共同作用

- **背景** 末档能走很久，但不满足直线运动目标。
- **问题** R2 独立组平均横偏 −2.51 m。在 5 个旧初态复跑也看到同向漂移和腿部不对称。
- **分析** 单靠世界 y 位移无法知道方向跑偏还是机器人本身侧滑/侧走。左右步长差与漂移同时出现，因果尚未对照。

### R3.2 原始混合 AMP 的稳定输出只有步行

- **背景** 保持一个 Actor、普通 D 和纯风格，先观察无命令的技能覆盖。
- **问题** 约 4.19M 首段末档仍常跌倒。5 个固定步行初态在 4.10M 有 1 个跑满，末档 0 个。慢跑初态多不足 1 s。
- **分析** 步行存活一度改善，支持一次有界追加。专家抽样失衡未得到证据支持。较难的慢跑初态、小数据和策略优化仍可能影响覆盖。
- **方法** 从 4.19M 继续追加相同预算，模型/归一化器加载，优化器、replay、RNG 与环境重新初始化。新增 30 步行和 30 慢跑相位，按速度、接触、姿态和持续窗口识别技能。
- **效果（部分解决）** 5.22M 起固定步行 5/5，8.389M 新步行 30/30。慢跑初态 21/30 减速转步行、9/30 跌倒，持续慢跑 0/30。首段外层采样只记录 442.21 s，缺完整 GPU 日志和退出码，终档和独立评估在。
- **新问题** 缓解技能覆盖不足需要可控指令。停止延长原始配置，保留慢跑初态减速和跌倒证据。
- **面试复习** 对“模式坍塌”给出证据强度。减速转为步行证明输出偏向，早跌倒只能证明该试次未完成，不确定是否存在未形成的慢跑策略。

### R3.3 速度条件和接触约束需要独立于参考初态

- **背景** 混合基线能走但不能指定走或跑，R1 的速度任务也暴露了爬行漏洞。
- **问题** 如果用参考运动类别决定命令，策略可能利用初态而忽略用户指令。如果只奖励速度，错误的支撑方式也能得分。
- **分析** 正式任务需要把目标速度和物理初态交叉。上游 steering 在 post-step 会更新下一指令，必须保留当前动作实际使用的指令。
- **方法** 用世界 +X 的 1.0/1.9 m/s 两档，Actor/Critic 在 237 个原物理观测后增加一维，不输入参考相位。继承 steering 速度/朝向奖励（0.7/0.3，速度项指数系数 2.0），任务与风格各 0.5。加入姿态、骨盆高度和非脚底触地终止，评估中明确快走/腾空差别。
- **效果（部分解决）** 普通 D 的 32,768 步 smoke 验证指令时序、奖励和训练更新。等物理状态的四种命令回合初态散列一致。约 4.194M 正式末档得到 25/32 目标步行，慢跑 0/32。
- **新问题** 起始姿态门限的定义需要在训练前和原始示范核对，另见下条。
- **面试复习** 一张图说清观测里的外部条件、速度任务与风格、当前动作和下一动作时间对齐。解释为何使用跌倒后的零速度补齐。
- **证据** [预注册 `3835634`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/3835634) · [任务配置](../configs/r3/speed_amp.json) · [实现](../scripts/r3_speed_amp.py) · [独立评估与普通 D 录像](../reports/R3_speed_amp.md#r3-2-普通判别器)

### R3.4 躯干倾角门限错拒慢跑前倾

- **背景** 公共规则要挡住爬行且允许正常的步态变化。
- **问题** 初版使用躯干倾角 50°。HOLD 的 `u4_jog_002` 约 32% 帧超过，最大 68.9°。128 环境首步 probe 有 11 个终止。
- **分析** 原假设“正常慢跑躯干倾角不会超过门限”与本批专家矛盾。骨盆倾角的全片最大为 39.7°，最低骨盆高为 0.751 m。因果上无法断言早停是学不到慢跑的唯一原因。
- **方法** 主动停止初版预跑（1,589,248 步，退出码 143），保留原试跑配置、日志和权重。从随机权重用同一修正版开始 A/B。检查骨盆≥0.66 m、倾角≤50°、非脚底实测触地力≤5 N。
- **效果（完全解决已识别的门限冲突）** 同 128 环境首步 probe 终止数 11→0，修订 smoke 正常通过。正式两组仍存在高倾角的真实闭环跌倒和慢跑缺失。
- **新问题** 限制过强的诊断得到纠正，下一步使用同初态、同预算分离条件 D 的行为差别。
- **面试复习** 区分 torso 与 root/pelvis 坐标和关节相对前倾。门限需先检专家和旧成功轨迹，也要检查是否仍能识别真实塌姿。
- **证据** [门限修订 `c2e093a`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/c2e093a) · [预跑与重新 smoke](../reports/R3_speed_amp.md#r3-2-smoke) · [本地保留的旧试跑](AMP_G1_ARTIFACT_INDEX.md#r3)

### R3.5 给判别器加条件时，回放不能丢标签

- **背景** 保留条件 Actor 后，要比较普通 D 与接收同一速度指令的 D。
- **问题** 如果 replay 以当前指令给历史 transition 重新贴标签，D 会把不同技能的运动与错误条件关联。切换点前后又有多个历史运动帧。
- **分析** 专家标签应来自实际 MotionLib 文件，策略标签应来自发出动作时的命令。一个运动窗口可跨切换，但每行所用条件必须与收集时一致。
- **方法** 两组相同的任务、命令、模型、数据、预算和 Actor/Critic 初始哈希。B 组把单一速度标量拼到运动历史末尾，与 rollout/replay 同写同抽。梯度惩罚只对运动特征求导。
- **效果（完全解决本轮标签路径）** D 2,390→2,391 维，Actor 保持 238。最终 smoke rollout 两档 2,013/2,083，2,048 个 replay 抽样两档 1,068/980，收集与取样检查通过。
- **新问题** 正确的标签路径只保证 A/B 可解释，不能替代速度、姿势和接触评估。
- **面试复习** 说明当步条件与下一状态指令的区别。讲为什么 replay 需要把行为历史与条件一起采样，以及仍存在跨指令运动窗口。
- **证据** [A/B 提交 `b00128e`](https://github.com/dreamerToTOE/Learning-for-AMP/commit/b00128e) · [标签实现](../scripts/r3_speed_amp.py) · [Smoke 结果](../reports/r3_speed_amp/conditional_smoke.json) · [模型与冻结清单](AMP_G1_ARTIFACT_INDEX.md#r3)

### R3.6 条件 D 加强速度响应，两个策略仍未学慢跑

- **背景** 用技能、指令跟踪与过渡判断条件 D 的实际效果。
- **问题** 两组在 1.9 m/s 下能加速但终段不腾空，完整切换未形成。慢跑初态更易早跌倒。
- **分析** 23 个两组两档都跑满的相同初态上，高命令使终段局部前速约增加 0.28 / 0.44 m/s。条件组有 4/48 窗口进入慢跑速度区间，普通组 0/50，两组均无合格双脚腾空。增加速度与形成慢跑动力学不同。
- **方法** 两组各 4,194,304 交互步、同训练 seed42。32 个新物理相位各做两档恒定和两种 5 s 切换。成功需跑满与末两窗口同时满足目标速度 MAE、支撑、腾空和姿态。
- **效果（慢跑与切换无明显改善）** 步行 25/32、24/32，慢跑均 0/32，跌倒各 7/32、8/32。降速后存活者能回到步行，因切换前没有持续慢跑，两方向完整切换均 0/32。高速前速 W1 0.569→0.462 m/s，关节运动 W1 未同步降低。
- **新问题** 高速初态早期失稳与幸存策略偏快走需分别解决。真实慢跑信号在后期仍缺，且只有一个训练 seed 和四段专家，因此按预算冻结。镜像、课程/自适应采样与多判别器留作二轮候选。
- **面试复习** 用已完成的快走证明速度响应，用零腾空和切换前后判据说明缺失技能。报告负结果和训练停止依据。
